# 研究数据采集与验证

Edgewise 使用同意研究的用户作为关联单位。问卷 A 指基于行为事件计算的指标，问卷 B 指用户主动回答的题目；前者不是用户自填问卷，也不能代替自评。实验组、事件、指标、问卷和后测通过用户 ID 关联。会话 ID、时间和其他字段仍可能识别个人。管理页面的会话和面板 JSONL 包含原始身份及内容，应按敏感数据处理。

`paper_empirical_analysis.md` 中的 400 条样本来自模拟数据脚本，不能作为真实研究结果。模拟脚本必须显式指定空的专用测试 Redis 并确认模拟写入；不要把模拟数据与研究参与者数据混用。

当前代码中的指标和题目见 [研究字段清单](./research_field_inventory.md)；该清单需要随研究规则和题库改动重新核对。

模拟稿中 P1–P6 与实际采集代码之间的具体差距见 [研究方案待核对项](./research_methodology_gaps.md)。

## 本地接手

当前开发环境的前端在 `127.0.0.1:3000`，后端接口文档在 `127.0.0.1:8000/docs`。本机后端使用 Redis 6380 和 MongoDB 27017，且启用了 `MONGODB_STRICT_LIVE`。其他开发环境使用各自的 `backend/.env`，仓库默认 Redis 端口是 6379。

| --- | --- | --- |
| 1 | [research.py](../backend/app/api/v1/research.py) | 同意、事件、问卷、后测和导出的接口及权限 |
| 2 | [events.py](../backend/app/research/events.py)、[derive.py](../backend/app/research/derive.py) | 问卷 A 的事件存储、重试回执、推导与证据 |
| 3 | [survey_items.yaml](../backend/app/research/survey_items.yaml)、[survey_engine.py](../backend/app/research/survey_engine.py) | 问卷 B 的题目、触发、下发、展示和保存 |
| 4 | [research_survey_service.py](../backend/app/services/research_survey_service.py)、[research_service.py](../backend/app/services/research_service.py) | 答卷验证、后测和研究导出 |

## 数据路径

1. 同意后分配 2×2 实验组。分配来源随用户记录保存，指定组别的记录应在论文分析时单独识别；均衡分配不等于简单随机分配。
2. 前端行为事件以 `{event, ts, props}` 上报，后端逐条校验格式、事件类型和同意状态，再存储原始事件并计算指标。成功的批次响应包含按输入顺序排列的逐条接收或拒绝结果；客户端在部分拒绝时记录警告。带稳定标识的事件重试会复用已确认的结果，未确认事件沿用原标识继续留在队列。指标元信息记录规则版本、计算时间和来源事件 ID；不是每个指标都有来源事件。
3. 问卷题目由 `backend/app/research/survey_items.yaml` 定义。按触发场景入队，返回到期且优先级靠前的题目；每次最多三题，受弹窗频率限制。答复包含状态、时间和题目版本。
4. `survey.enqueued`、`survey.offered`、`survey.shown` 分别记录入队、下发和客户端上报展示。新版展示回执与答卷共享 `offer_event_id`，管理统计只计入能匹配下发记录的展示。浏览器回执无法确认参与者实际阅读。跳过、拒答和未作答应与数值 0 区分。
5. 新后测采用两个独立评分名额。本人不可评分，每位评分者只提交一次完整分项，另一位评分者看不到已提交的分数。会话导出保留原始分项与提交时间。旧盲评队列沿用原来的单评和重试流程。答案文本本身可能暴露身份，正式评分者资格、分歧处理和总分规则待定。
6. 管理面板 JSONL 导出包含分组、行为指标、指标元信息和问卷；CSV 包含指标和问卷 JSON、元信息 JSON 及分配来源。规则版本和问卷定义应与研究方案、实际导出时间一起归档。旧答案可能没有逐题版本，不能推定其版本。
7. 研究事件 JSONL 包含当前同意周期内已写入持久存储的结构化事件。导出使用与伪名化会话和面板导出一致的用户伪名，保留事件 ID、发生时间、接收时间及用于关联的字段。
8. 导出接口要求管理员权限，并通过 `Cache-Control: no-store` 禁止 HTTP 缓存保存响应。事件、会话和面板导出会在 Redis 滚动审计中记录操作者、时间、导出类型、格式和是否使用伪名。审计参数仅保存这些操作信息。

事件、会话、问卷面板和推荐关联使用同一套导出伪名。正式采集前请为同一研究设置并固定独立的 `RESEARCH_HASH_SECRET`。未配置时使用 `JWT_SECRET`。更换用于导出的密钥会改变伪名，改用新算法之前的开发导出也需要重新生成才能关联。默认伪名面板保留开放题的回答状态和时间，原文仅通过管理员的显式原始导出获取。伪名会话 CSV 留空自定义主题、评分详情、渠道标签及拒绝修改的文字理由。
9. 管理员时间线与长表按当前有效的同意周期筛选。事件须满足同意开始后的发生和接收时间，已有周期标记也须一致。冷缓存下会从 MongoDB 读取答卷。没有有效同意的账号不提供研究时间线。
10. 管理统计和会话导出只使用当前同意周期内可核对的后测到期与完成时间。缺少相应完成时间时，面板也会排除旧的 `J1`、后测答案和完成标记。重新同意后的后测安排仍待研究方案确认。
11. 第十四天自愿任务以当前同意周期内的开放时间为准。后端在创建会话时保存开放依据，面板输出已核验会话的首次完成时间。旧二元指标查询的是开放前窗口，已从研究面板移除。正式自愿练习的观察窗口和分母待研究方案确认。

作答、反馈和修改事件保留会话标识及结构化证据。拒绝修改只导出是否填写理由，理由原文留在原始记录中。观察窗口和跨会话处理口径待研究方案确认。

## 存储与恢复边界

- 正式和预发布环境要求 MongoDB 可连接。开发环境可降级到本地 JSON；该模式不支持多进程安全写入，不应作为正式研究存储。
- 正式和预发布环境需要独立的 MongoDB 与 Redis，并设置随机 `JWT_SECRET`。启动时仅初始化公共题库与内容，发现旧演示管理员时会中止启动。管理权限由部署方为真实管理账号配置。
- Redis 仍保存索引、实验分组计数及其他运行数据。部分研究数据已写入 MongoDB 并支持冷缓存读取，但这不等于所有键都可恢复。清空、替换或重建 Redis 前，必须另行备份并逐类验证。
- 使用 MongoDB 时，后端启动会创建按用户查询事件和按状态查询卡住回执的索引。部署账号需要目标数据库的索引创建权限。
- 答卷优先读取 MongoDB 已保存的逐题记录，Redis 只补充尚未迁移的旧题目。旧数据迁移只补缺失题目，不覆盖持久化答卷。新答卷在 MongoDB 保存后更新 Redis。
- 问卷 A 的新指标值和来源元信息在同一 MongoDB 文档中写入。读取时持久化值优先，迁移仅补充缺失字段，保留已保存的空值。旧指标和单独存放的来源元信息仍可读取。
- 恢复连接时，只自动复制 MongoDB 中不存在的降级文档；内容冲突留在本地并记录错误。检查管理员存储状态中的 `pending_fallback_collections`，人工比对后再处理冲突。
- 新离线事件按账号隔离，旧的无账号标记队列不自动归属用户。支持安全随机数的浏览器为事件生成稳定编号，重试沿用同一编号。Redis 写入、MongoDB 回执、指标和触发各有恢复断点。缺少稳定编号或停在未确认的副作用阶段时仍需核对。[事件恢复说明](./research_event_reliability_plan.md)
- 新客户端只在本地记录到有效同意及开始时间时创建事件，并附带同意周期开始时间；服务端拒绝与当前周期不一致的标记。曾记录拒绝或撤回的用户，其没有周期标记的旧客户端事件也会被拒绝；从未记录拒绝的旧客户端事件为了兼容仍可能被接受，不能证明它们发生在同意后。客户端状态可能过期，且撤回与并发请求之间尚无事务隔离。
- 面板中“已记录触发/展示”只统计已有证据的用户，不能视为完整漏斗；缺少完整历史时不计算相关比例。展示后关闭页面、离线失败及研究事件的采样上限都可能产生缺失。

## 上线前验证

1. 在隔离数据库使用测试账号，依次验证注册、同意、分组、练习、事件、问卷入队与答复、七日后测、盲评和管理员导出。确认每个论文字段的事件、推导规则、题目及缺失状态。
2. 以真实 MongoDB 和独立 Redis 测试正常读写、Redis 丢失后的恢复、数据库不可用时生产启动失败，以及降级文件与数据库冲突保留。核对总数、内容、版本和来源，不以连接成功代替数据核对。
3. 测试并发分组与计数恢复；核对被指定组别、未分组和撤回同意的样本。论文分析应依据实际分配方案和导出字段定义样本，不将均衡分配直接描述为完全随机。
4. 验证真实浏览器中问卷展示和事件网络请求；项目自定义的分层检查包含静态源码检查，不能代替浏览器端到端测试。
5. 根据知情同意书确定撤回后的既有数据处理、原始文本访问、留存期和导出范围。当前撤回会阻止一般客户端研究事件、问卷答复与后测提交，并清理问卷队列等状态；同意变更等特定服务器事件仍会记录。待盲评答案在撤回期间暂停展示和评分；新入队答案记录同意周期，重新同意后旧周期答案继续暂停。无周期标记的旧答案在存在拒绝或撤回记录时暂停；没有拒绝记录也不能证明历史答案的来源。记录不会因此自动删除，撤回与同时到达的请求也不具备事务隔离。
6. 会话 JSONL/CSV 导出仅包含当前同意周期开始后创建、且创建时标记为研究可用的完成会话；缺少可信时间或标记的历史会话暂不导出。重新同意前的会话也暂不导出，原始会话不删除。用户已同意时重复确认不会重置该周期起点；最终追溯使用规则仍需同意书和研究方案确认。
7. 问卷 B 的新答复记录同意周期。问卷触发和面板导出排除旧周期答复；有拒绝或撤回记录时也排除无周期标记的旧答复。覆盖旧周期答复前会归档原记录。有拒绝或撤回记录的账号按同意周期存储问卷 A 的指标与来源信息，周期之间不继承计数。每日聚合仅使用接收和发生时间均在当前同意之后的事件。对于有拒绝或撤回记录的账号，含会话 ID 的事件还会核对会话归属、创建时间和研究标记。研究面板在读取时按双方当前同意状态重算推荐人数。邀请人重新同意后，只计入能证实在该周期内绑定的邀请。该计数尚未应用正式研究的推荐观察窗口。缺少会话 ID 的事件仍需逐项核查，计算时间不能单独证明来源的同意状态。JSONL/CSV 包含当前同意时间、是否记录过拒绝及 `data_scope=consent_cycle_not_verified` 提示；未记录拒绝也不能证明不存在更早数据。核实数据来源和最终处理规则前，不应将面板数据视为当前周期的完整研究样本。

在仓库根目录运行以下命令。先确保前端开发服务器可访问，再运行集成验收。

```bash
npm run test:backend
EDGEWISE_TEST_MONGO_URI=mongodb://127.0.0.1:27017 backend/.venv/bin/python scripts/research_smoke.py
```

后端测试使用临时目录、测试环境和预留但未监听的本机端口。集成脚本需要 Redis Server、macOS Google Chrome 和 Python 后端依赖，启动独立 Redis，并在指定 MongoDB 实例创建随机命名的测试数据库，完成后删除该测试数据库。仅为 `EDGEWISE_TEST_MONGO_URI` 指定开发或测试实例。未设置该变量时，集成脚本使用本地 JSON 降级模式。

真实 MongoDB 模式还会演练备份恢复。用隔离 Redis 生成 RDB，用 BSON 文件保存合成样本的 MongoDB 文档及索引定义。在临时数据库上恢复并核对索引后，启动临时 API，核对事件导出、问卷 A 指标及来源事件、问卷 B 逐题答复和十四日随访完成时间。正式部署仍需验证数据库账号权限、在线写入期间的双库一致性和备份保留策略。
