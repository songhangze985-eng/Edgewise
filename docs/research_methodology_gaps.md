# 研究方案与当前采集代码：待核对项

本清单依据当前题库、事件处理代码和已有模拟分析稿整理。模拟稿不是已完成的研究方案，也不是实证证据；以下判断是代码核对结果，不能证明测量有效。正式采集前需要由研究负责人确认操作定义、观察窗口和分析方案。

候选定义见 [测量口径草案](./research_measurement_proposal.md)；其中的窗口和公式仅供审阅，尚未生效。

| 命题 | 当前已有的采集或计算 | 需要确认或补齐 |
| --- | --- | --- |
| P1 触点连续性 | 有 `C1`、`C4`–`C6` 题目；代码可从事件属性推导 `time_to_first_answer_sec`、`steps_to_first_answer` 和 `entry_reselect_count`。任务页另有 `task.steps_to_start`，生成的是 `task_time_to_start_ms` 和 `task_steps_to_start`。 | 练习会话导出已提供后端记录的会话创建时间和评分接口首次通过有效性检查的接收时间。任务页 CTA 记录可按当前同意周期、任务和会话关联到导出。任务到启动的步数沿用现有里程碑计数，普通大厅入口和完整操作序列仍待定义。“任务页到启动”不一定等于“入口到首次作答”。应先确定计时起点、终点、单位、重选和中断规则，再实现和验证。 |
| P2 主动演练与迁移 | 有 `F3a`–`F3c`、`F5a`–`F5c`、`J2`，七日后测及四个盲评分项。 | 新后测试行两位不同评分者独立提交四项 1–5 分，旧队列保留原流程。正式评分者人数、资格、分歧处理与 0–100 分换算仍需确认。模拟分析中的 `posttest_score` 和管理交叉表中的 `blind_score_mean` 不能假定已由现有流程生成。 |
| P3 合格激活 | `qualified_activation` 根据有效作答、查看反馈及修改或有理由拒绝等事件推导。 | 产品内部仍可能先写 0。研究面板导出把未确认状态输出为空，分组页只显示确认和未确认人数。正式分析需确定截止时间、未观察到的处理和重复事件规则。 |
| P4 信息诊断性 | 有 `D1`、`D2`、`D3`、`D5`、`D6`、`F4a`、`F4b` 等题目及创作者系列记录。 | 新曝光记录区分计划版本和实际进入视口的内容版本，并记录系列、单集与内容指纹。专栏页面标识与练习链接点击标识可把单集曝光、链接点击、任务 CTA 及后续会话关联起来。正式曝光口径、适用样本及随机分配规则仍需确认。 |
| P5 建议相关性与延迟 | 有 `E1`、`E2`。Copilot 分别记录浏览器诊断请求耗时和服务端规则耗时。通过任务页或面试大厅建议进入的练习会话，可导出经后端核验的诊断 ID、建议记录时间和会话创建时间。 | 正式延迟指标、转化窗口和归因规则待确认。当前会话关联覆盖任务页和一对一面试大厅。 |
| P6 激励与传播 | 面板导出包含激励分配时间与来源、仍符合双方同意条件的推荐绑定，以及合格激活的来源事件和计算时间。代码另有 `referral_qualified_invitees`、`invitees_valid_practice` 和 `I1`–`I4`、`G4` 等题目。 | 产品使用 `task_equity`、`cash`、`none`，模拟分析使用 `bonus_practice`、`cash_rebate`；编码映射、激励实际发放、合格受邀人的观察窗口及去重要在分析前明确。 |

当前采用均衡分组，指定组别以 `experiment_assignment.source` 标记。带稳定编号的事件支持重试去重，缺少编号的历史事件以及多来源上报同一业务动作仍需按具体指标审计。问卷展示回执表明浏览器上报了展示。缺失、未到期、主动跳过、拒答与技术失败分别处理，无法判定的值留空。

建议先确认各命题的字段定义和时间窗口，再用隔离测试账号逐项验证事件 → 指标 → 问卷 → 导出的原始记录。真实样本开始采集后，应冻结版本并保留变更记录。
